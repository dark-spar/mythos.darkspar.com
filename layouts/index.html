Mythos is a single-binary media server with an embedded SvelteKit UI. It scans your library, enriches metadata from TMDb, and streams direct-play when it can — hardware-accelerated HLS when it can't. Movies today; TV, music, photos, and books are scheduled.

What works today

Six things Mythos already does.

  1. 01

    Single binary, embedded UI.

    The SvelteKit build is baked into the Rust binary via rust-embed. One file boots the server and serves the SPA.

  2. 02

    Library scan + TMDb enrichment.

    Parallel filesystem walk via jwalk, technical metadata via ffprobe, titles and posters from TMDb. Posters are proxied locally so clients never hit TMDb directly.

  3. 03

    Direct play with byte ranges.

    If your browser can decode the file, Mythos streams it raw with HTTP range requests. Resume points are debounced and persisted.

  4. 04

    HLS transcoding when needed.

    For browser-incompatible codecs (HEVC, AV1, DTS, …) Mythos spawns an ffmpeg session, segments to HLS, and tears it down when the player goes away.

  5. 05

    Hardware-accelerated, smoke-tested.

    NVENC, QSV, VAAPI, and VideoToolbox are probed and smoke-tested at startup, so a build with the encoder compiled in but a missing driver falls back to CPU cleanly.

  6. 06

    Subtitles done right.

    Text subtitles ride along as WebVTT sidecars. Image subtitles (PGS/VobSub) burn in during transcode so they survive every device.

Where we are

Roadmap — track the phase, don't pull work forward.

phase 0 — 1

Done (movies-only slice). Workspace, embedded SPA, axum boot, SQLite + migrations, argon2id + HS256 JWTs (cookie or Bearer), libraries CRUD, movies scanner + browse UI, TMDb enrichment with an admin-editable key.

phase 2

Done. Direct-play streaming with byte-range support, Vidstack source binding, debounced watch progress, resume.

phase 4 — 5

Done. Phase 4 ships HLS transcoding for incompatible media. Phase 5 lights up hardware acceleration (NVENC / QSV / VAAPI / VT), multi-rendition ABR, subtitle burn-in, and client-declared device profiles.

phase 3 + 6

Next. Phase 3 brings TV series, music, photos, and books. Phase 6 adds a Jellyfin-API-compatible shim so existing clients (Findroid, Swiftfin, jellyfin-web) work against Mythos.

Get started

Build from source — that's the path for now.

cargo run

One command builds the SPA (via pnpm build) and the Rust binary, then boots the server on 127.0.0.1:8080.

git clone https://gitlab.com/darkspar/mythos
cd mythos
cargo run --release --bin mythos-server

prerequisites

The build needs a working Rust toolchain, Node + pnpm for the SPA, and ffmpeg/ffprobe on PATH for scans and transcodes.

rustup 1.95+
node 22+
pnpm 10+
ffmpeg / ffprobe

iterate

Skip the SPA build when you're only touching Rust. Run the Vite dev server when you're only touching the UI.

MYTHOS_SKIP_WEB_BUILD=1 \
  cargo run --bin mythos-server

cd web && pnpm dev

configure

Defaults work out of the box. Override via ./mythos.toml or any MYTHOS_* env var — env wins.

listen     = "0.0.0.0:8080"
data_dir   = "/var/lib/mythos"
log_filter = "info,mythos=debug"

Early, but real.

Mythos streams movies with hardware-accelerated transcoding today. The roadmap is public, the source is MIT, and the binary is one cargo build away.
